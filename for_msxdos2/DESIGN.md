# DOS2版 ZMA 設計メモ

- 作成： 2026-11-10
- 対象： クロスアセンブラ ZMA（v1.0.20）の MSX-DOS2 ネイティブ版 **「ZMA for MSX-DOS2」**
- 実装言語： Z80 アセンブラ（クロス版 ZMA の文法で記述し、クロス版 ZMA でビルドする。最終的には DOS2版自身でビルドできること＝セルフホストを目標とする）
- 実行環境： MSX-DOS2、メモリーマッパー使用可

## 0. 方針

- クロス版 ZMA と「ほぼ等価」を目指す。等価の基準は **同じ入力ソースに対して同じ出力バイナリ（および同等のシンボル情報）を返すこと** とし、検証はクロス版とのバイト比較で機械的に行う。
- 実装は段階分けし、各段階で比較検証を通してから次へ進む。
- DOS2 版で設ける制限は本書 §4 に明示する。制限に触れた場合は黙って誤動作せず、必ずエラーにする。

## 1. クロス版 ZMA の仕様サマリ（移植対象）

出典は `zma_doc.md`（v1.0.20）。DOS2 版が扱うべき意味論の要点は次のとおり。

### 1.1 命令セット

- Z80 全命令＋未定義命令（IXH/IXL/IYH/IYL 等）＋R800 乗算命令（MULUB/MULUW）。
- ザイログ表記からの変更点： 間接参照は `[]`、ポート番号も `[]`、`JP HL` 形、演算命令の A 明記（旧記法も一部受理）。

### 1.2 疑似命令

ORG / DEFB / DEFW / DEFD / DEFS（`-DEFS` オプションで意味が変わる）/ SPACE / ALIGN / INCLUDE / ADD_INCLUDE_PATH / BINARY_LINK / MACRO～ENDM / SCOPE～ENDSCOPE / REPEAT～ENDR / IF～ELSEIF～ELSE～ENDIF / CHG_CHAR_SET / MAPPING_CHAR / MESSAGE / ERROR / LINK～ENDL。

### 1.3 シンボルの意味論（重要）

- ラベルには **ローカル**（`名前:`、スコープ内でのみ有効）と **グローバル**（`名前::`、どこからでも参照可）がある。参照時は内側のスコープのローカルが優先される。
- 代入は `名前 = 式`（ローカル）と `名前 := 式`（グローバル）。**記述順序は無関係**で、1つのラベルに1つの値だけが紐付く。つまり代入は逐次実行ではなく **方程式の解決** として扱われる。
- シンボルの値は数値だけでなく **文字列** も取れる。
- ローカルラベルの有効範囲は SCOPE と REPEAT が作るスコープで決まる（REPEAT の回数式は外側スコープで評価される）。

### 1.4 MACRO

- 引数は単純なテキスト置換。`@引数` は文字列化され、その際 **大文字化＋トークン間を半角スペース1つに正規化** される（この正規化結果が IF の文字列比較に影響するため、等価性のためには一字一句合わせる必要がある）。
- MACRO / REPEAT / IF の中ではマクロ宣言できない。

### 1.5 IF の循環依存（最難関）

- 通常は条件式を評価して分岐を選ぶが、条件が後方ラベルを参照し、そのアドレスが分岐自体に依存する循環ケースでは **候補探索** を行う。
  - 候補＝各 IF の分岐選択の組み合わせ。各候補は独立した状態で解析する。
  - 採用条件： 最終的なラベル値・アドレスで条件式を再評価した結果が、選択した分岐と一致し、選択された命令にエラーがないこと。
  - 複数の有効候補がある場合は **出力バイト数が最小** のもの、同サイズなら探索順（IF、ELSEIF、ELSE、無出力の順）で先のもの。
  - 探索は分岐仮定を含めて最大 **1,024 回** の候補評価まで。上限到達で未評価候補が残ればエラー。整合する候補が無ければエラー。未定義シンボルを推測で補完しない。
  - 不採用候補のメッセージ・エラー・シンボルは結果に反映しない。

### 1.6 LINK

- `LINK トリガー名... ～ ENDL` は遅延展開ブロック。外側の式の中でトリガー名が使われたときに内容が展開される。シンボル解決の不動点計算と一体で扱う必要がある。

### 1.7 式

- 数値式： 演算子は優先順位11段（単項 + - ! ~、`* / %`、`+ -`、`<< >>`、比較、==/!=、`& ^ |`、`&& ||`）。値は符号付き整数。
- 定数： `$`（行の開始コードアドレス）、`$$`（ファイル内アドレス）、CODE_ADDRESS、FILE_ADDRESS、CHAR_SET_NAME（文字列）。
- 文字列式： 連結と比較が可能。文字コードは現在のキャラセットで解釈される。

### 1.8 文字セット

- CHG_CHAR_SET で名前付きキャラセットへ切替（"DEFAULT" は ASCII）。MAPPING_CHAR で対応を変更（範囲指定可、DEFAULT は変更不可）。キャラセット定義の実体はクロス版の同梱データを踏襲する。

### 1.9 入出力・CLI

- 実行形式： `zma [-options] <input.asm> <output.bin>`
- オプション： `-DEFS`、`-HELP/-H`、`-I<パス>`、`-D<名前>=<値>`（文字列値はシングルクオート）、`-HEX`（Intel HEX 出力）。
- 終了コード： 成功 0、エラー 1。エラー詳細は標準エラー出力と `zma.log`、シンボル一覧は `zma.sym` に出る。
- エラーメッセージ文言はクロス版（英語）を踏襲する。

## 2. 全体アーキテクチャ

### 2.1 処理モデル

DOS2 版の中核は「2パス」ではなく、クロス版の意味論に合わせた次の2層で構成する。

1. **不動点反復**： ソース全体の処理を、シンボル値が安定する（前回と同じ値に収束する）まで繰り返す。前方参照ラベルと、順序非依存の代入（§1.3）はこの反復で解決する。未確定のシンボルを参照する式は「未確定」を伝播させ、確定するまでエラーにしない。
2. **IF 候補探索**： 循環依存する IF に限って §1.5 の探索を行う。探索では状態のスナップショットと復元が必須になる（§2.4）。

出力（コード生成）は、値が確定した最終反復でのみ実ファイルへ書き出す。それ以外の反復はアドレス計算と検証だけを行う「ドライラン」とし、出力先を切り替えるだけで同じ処理系を使い回す。

### 2.2 入力スタック

文字の供給元を統一したスタック構造にする。

| 供給元 | 実体 | 位置の保存・復元 |
|---|---|---|
| ファイル | DOS2 ハンドル＋行バッファ | ファイルオフセット（_SEEK で復元可） |
| MACRO 展開 | セグメント上の本体テキスト | セグメント番号＋オフセット |
| REPEAT 展開 | 同上＋ループ変数・残回数 | 同上 |
| LINK 展開 | 同上 | 同上 |

- INCLUDE はファイル供給元の入れ子として扱う。
- **ネスト制限（確定事項）**： MACRO 呼び出し＋SCOPE＋REPEAT の合算深度は **最大 8**。これを超えたらエラーにする（作者了承済み、2026-11-10）。
- パス反復時はスタックを初期化し、入力ファイルは先頭から読み直す。

### 2.3 メモリ配置とマッパー利用

- 本体は .COM 形式で 0100h から配置。実行ファイル名は **ZMA.COM**（作者指定）。常駐メモリにはコード、入力スタック、行バッファ、ハッシュ表などの「熱い」データだけを置く。
- 大容量データは EXTBIO 経由で得るマッパーサポートルーチン（ALL_SEG / FRE_SEG 等）で確保したセグメントに置き、ページ1（4000h〜7FFFh）を窓として切り替える。終了時に全セグメントを解放する。
- セグメント割当ての案（16KB 単位、必要数だけ確保）：

| 用途 | 内容 |
|---|---|
| シンボル値配列 | シンボル ID 順に「型タグ＋値（数値4バイト or 文字列参照）」。候補探索のスナップショット対象 |
| シンボル名プール | 名前の実体（長さ＋文字列） |
| MACRO / LINK 本体プール | 定義テキストの実体 |
| 文字列プール | 文字列シンボルの値、マクロの @引数 の正規化結果など |
| スナップショット退避 | 候補探索用に値配列を退避する領域 |

- 規模の目安： baconlib.asm（10,827行、シンボル約3,400件、スコープ付き）で、値配列は約27KB（8バイト/件×3,400）、名前プールは数十KB級。マッパー総容量 256KB の標準的な環境でも十分に収まる。

### 2.4 状態スナップショット（候補探索用）

候補ごとに独立した解析を行うため、次の状態を保存・復元できるようにする。

- シンボル値配列（§2.3 のセグメントを退避領域へコピー）
- 現在のコードアドレス、出力ファイル位置
- スコープスタック、入力スタック全体（§2.2 の位置情報で復元可能）
- キャラセットの現在状態（MAPPING_CHAR の変更を含む）

入力位置が「ファイルオフセット or セグメント内オフセット」で一意に復元できることが、入力スタックをこの形にした理由である。

### 2.5 式評価器

- 再帰下降で §1.7 の優先順位をそのまま実装する。値は32ビット符号付きとして扱う（内部表現は4バイト固定）。
- 未確定シンボル参照は専用の状態値で伝播させる。確定パスでのみ 0 除算などの実エラーを報告する。
- `$` / `$$` は現在の入力位置と出力状態から供給する。STRING 値の式（連結・比較）は文字列プール上の参照で扱う。

### 2.6 出力

- バイナリは出力バッファ（常駐メモリ）経由で DOS2 ハンドル API の _WRITE にまとめて書く。ORG でアドレスが飛ぶ場合の隙間の扱いはクロス版仕様に合わせる。
- Intel HEX（`-HEX`）はレコード単位の整形のみで、同じ出力層の別フォーマッタとして実装する。

### 2.7 文字セット

- キャラセット定義（名前、256バイト変換表、MAPPING_CHAR による変更の蓄積）はセグメント上に置く。
- 文字列リテラルと DEFB 文字列は、出力時点で現在の変換表を通す。

### 2.8 ファイル I/O と起動

- ファイル操作は MSX-DOS2 のハンドル API を使う（_OPEN 43h / _CREATE 44h / _CLOSE 45h / _READ 48h / _WRITE 49h / _SEEK 4Ah）。
- コマンドラインは DOS2 のコマンドテール（0080h〜）を自前で解析し、クロス版と同じ `[-options] input output` 形式とオプション（-DEFS / -I / -D / -HEX）を受ける。
- ファイル名は **8.3 形式のみ** 対応とする（ロングファイル名は非対応。確定事項 §7）。
- 異常終了時も含め、確保したマッパーセグメントと開いたハンドルは必ず解放・クローズしてから DOS2 へ戻る。

## 3. 制限一覧（DOS2 版で設けるもの）

| 項目 | 制限 | 備考 |
|---|---|---|
| MACRO＋SCOPE＋REPEAT の合算ネスト | 最大 8（確定） | 超過はエラー |
| REPEAT の反復回数 | 最大 16,384（2026-11-13 作者裁定） | 超過はエラー。クロス版には無い DOS2 独自制限 |
| REPEAT のネスト | 最大 2（2026-11-13 作者裁定） | REPEAT の入れ子のみが対象。合算ネスト上限 8 は不変 |
| IF 候補探索の評価回数 | 最大 1,024（クロス版踏襲） | 上限到達はエラー |
| INCLUDE のファイルネスト | 最大 4（確定） | ハンドル数と入力スタックの都合 |
| 1行の長さ | 最大 255 バイト（確定） | 超過はエラー |
| シンボル名の長さ | 最大 63 バイト（確定） | スコープ修飾後の内部名も同じ上限 |
| 不動点反復の回数 | 最大 32（案） | 収束しなければエラーとして報告 |

## 4. 実装フェーズと合格条件

検証は各フェーズとも「クロス版 ZMA と出力バイナリがバイト一致すること」。コーパスは §5。

| フェーズ | 内容 | 合格条件 |
|---|---|---|
| P1 コア | 行読み・字句解析、全ニーモニックのコード生成、数値式、ラベル（`:` / `::`）、基本疑似命令（ORG / DEFB / DEFW / DEFD / DEFS / SPACE / ALIGN / INCLUDE）、不動点反復、バイナリ出力 | baconloader.asm と ZMA 付属サンプルが一致 |
| P2 シンボル意味論 | 代入（`=` / `:=`）、文字列値と文字列式、SCOPE とローカルラベル、`-D`、MESSAGE / ERROR | スコープ・代入系の自作テスト一式が一致 |
| P3 展開機構 | MACRO、REPEAT、LINK、ネスト制限 8 | **baconlib.asm がバイト一致** |
| P4 仕上げ | IF 候補探索、CHG_CHAR_SET / MAPPING_CHAR、BYNARY_LINK、Intel HEX | 全コーパス一致 |
| P5 セルフホスト | DOS2 版 ZMA 自身のソースを DOS2 版でアセンブル | クロス版の出力と一致 |

## 5. 検証コーパス

- `baconloader.asm`（63行。P1 の最初の関門）
- `baconlib.asm`（10,827行。マクロ・スコープ・ラベル代入を多用する実戦コーパス）
- クロス版 ZMA 付属の sample / include（MSXDOS1.ASM、MSXDOS2.ASM、STDIO.ASM、STRING.ASM 等）
- 機能別の小テスト（IF 循環依存、LINK 遅延展開、@引数の正規化など、仕様書の例題をそのまま使う）

## 6. リスク

- **速度**： Z80（3.58MHz）では不動点反復の回数×ソース規模がそのまま効く。baconlib 級で数十秒〜分オーダーの可能性があり、見積りは P1 完成時に実測して再評価する。R800（turboR）では大幅に改善する見込み。
- **IF 候補探索の状態管理**： スナップショット漏れ（キャラセット変更、スコープ状態など）があると不採用候補の副作用が漏れて等価性が崩れる。§2.4 の対象リストを実装時にチェックリストとして使う。
- **文字列化の正規化**： @引数の大文字化・空白正規化がクロス版と1バイトでも違うと、文字列比較を使うマクロで結果が変わる。P3 で専用テストを作る。

## 7. 決定事項（2026-11-10 作者裁定）

1. 製品名は **「ZMA for MSX-DOS2」** とする。
2. INCLUDE ネスト上限は **4**。
3. 1行の長さは **最大 255 バイト**、シンボル名は **最大 63 バイト**。
4. リスト出力（.LST 相当）は **作らない**。出力はバイナリ／Intel HEX と、クロス版 ZMA が出すログ（zma.log／zma.sym 相当）のみでよい。
5. ファイル名は **8.3 形式のみ** 対応（ロングファイル名は非対応）。それ以外のヘルプ・画面表示・メッセージは **クロス版 ZMA に寄せる**。実装が困難なもの、労力の割に実用度が極めて低いものがあれば、その都度作者に相談する。
6. 本体の動作対象は **Z80 のみ**（R800 検出による高速化パスは用意しない）。
7. （2026-11-13 作者裁定）**REPEAT の反復回数は最大 16,384 回**、**REPEAT のネストは最大 2** とする。根拠は作者判断「早送りして600秒で終わらないケースは実用ケースではない」。いずれもクロス版には無い **DOS2 独自制限** で、超過時は黙って誤動作せずエラーにする。REPEAT ネスト制限は REPEAT の入れ子のみを対象とし、§3 の MACRO＋SCOPE＋REPEAT 合算ネスト上限 8 は変更しない。
8. （2026-11-13 作者裁定）**DOS2 版の `zma.log` は省略形とする**。内容は次の2つだけである： (1) エラーまたは警告が出た行について、その行番号と行の内容（エラーメッセージを含む）。(2) 定義シンボルの一覧（従来の `<< label >>` 節）。行イメージの全行出力（`<< code >>` 節）、`<< character map >>` 節、その他は出さない。これはクロス版の完全ログからの **意図的相違** であり、決定 4 の「クロス版 ZMA が出すログ相当」は zma.log については本項が優先する（`zma.sym` は従来どおり）。長年の判断待ち事項だった「小容量メディア向け zma.log 抑制」は、本裁定をもって **決着** とする（抑制スイッチではなく形式そのものの変更）。背景： クロス版準拠の完全ログは REPEAT 16384 のソースで約1.67MB となり 720KB メディアに収まらなかった。コンソール表示と終了挙動は不変。
